# 程式架構

本文說明期中展示版的程式如何分層、各層可以依賴誰，以及新增內容時該改哪裡。程式不經建置，以瀏覽器原生的 ES 模組（ES modules，每個檔案以 `import` / `export` 明確宣告相依）載入，進入點是 `src/main.js`。

## 分層

程式分為七層，由下而上依序是 `data`、`core`、`rules`、`ui` 與 `art`、`audio`、`scenes`，最上方是 `main.js`。原則是下層不知道上層存在：資料不知道規則，規則不知道畫面，畫面才把規則與繪圖組合起來。

`data/` 只放純資料，例如部門清單與其在人體圖上的座標、早上行程選項、怨氣門檻、員工手冊內文。這一層沒有任何邏輯，也不 import 其他層，調整選項文字或門檻數字時只需改這裡。

`core/` 是共用的基礎設施。`state.js` 匯出唯一的遊戲狀態物件 `S`，重新開局時就地重設，因此其他模組 import 到的 `S` 永遠指向目前這一局；`scenes.js` 負責場景註冊與切換；`events.js` 是極簡的發布與訂閱機制；`feedback.js` 提供提示便條（toast）與部門對話泡泡（say），兩者都只把訊息放進狀態，由畫面層負責畫出來。

`rules/` 是遊戲規則，只讀寫狀態，不呼叫任何繪圖函式，也不切換場景。行程與待命池的計算在 `planning.js`，白天的腳本事件與時鐘在 `timeline.js`，調度危機在 `crisis.js`，晚上的事件卡在 `evening-event.js`，睡眠、讀書效率與考試分數的公式在 `sleep.js`，倒閉報告的追溯文字在 `report.js`。規則需要讓外界知道「發生了什麼事」時（例如危機開始、代幣被移動、睡眠結算完成），只透過 `events.js` 發出事件，不直接播放音效。由於這一層與畫面無關，可以在瀏覽器主控台直接 import 並以腳本驅動，用來做回歸測試。

`ui/` 是與遊戲內容無關的介面元件：畫布縮放與指標座標（`canvas.js`）、配色與字型（`theme.js`）、筆記本背景與共用繪圖函式（`draw.js`）、按鈕與目前畫面的按鈕清單（`button.js`）、提示便條與靜音按鈕。`art/` 放人體與小晨的向量圖形資料，以及器官員工插圖的載入和依怨氣切換狀態的邏輯。

`audio/` 由四個檔案組成。`mixer.js` 管理音訊環境、主音量總線與全域靜音，並在使用者第一次點擊或按鍵時才啟動，以符合瀏覽器的自動播放限制；`music.js` 是背景音樂播放清單；`sfx.js` 以 Web Audio API 即時合成音效；`cues.js` 訂閱遊戲事件，決定哪個事件播放哪個音效。想改某個時機的音效，只需改 `cues.js`，不必碰規則。

`scenes/` 每個檔案是一個畫面，負責繪製與把滑鼠、鍵盤操作轉成規則呼叫，並在載入時向 `core/scenes.js` 註冊自己。白天畫面較複雜，拆在 `scenes/day/`：`layout.js` 集中畫面座標，供繪製與點擊判定共用；`body-map.js` 畫左側人體圖；`panel.js` 畫右側員工卡、待命池、危機框與跑馬燈；`event-card.js` 畫事件卡；`index.js` 是場景本體，依「一般、危機、事件卡」三種狀態決定要顯示哪組按鈕。

`main.js` 把 p5.js 全域模式需要的 `preload`、`setup`、`draw` 與輸入回呼掛到 `window` 上，再分派給目前的場景。ES 模組在頁面的 load 事件之前執行，而 p5 在 load 事件時才啟動，所以在模組裡設定這些回呼來得及。

## 相依規則

各層可以 import 的對象整理如下；不在表中的方向（例如 `rules` import `scenes`，或 `ui` import `rules`）都不應出現。

| 層 | 可以 import |
| --- | --- |
| `data` | （無） |
| `core` | `data`、`ui/button.js`（切換場景時清空按鈕） |
| `rules` | `core`、`data` |
| `ui` | `core`（狀態與事件）、`audio/mixer.js`（靜音按鈕） |
| `art` | `core`、`data`、`ui` |
| `audio` | `core` |
| `scenes` | 以上全部 |
| `main.js` | 以上全部 |

## 常見修改

新增一個早上行程選項時，在 `data/choices.js` 的 `CHOICES` 加一筆；若它會佔用代幣，加上 `brain` 或 `muscle` 欄位，`rules/planning.js` 會自動算進待命池。新增白天腳本事件時，在 `rules/timeline.js` 的 `runBeats` 加一個 `beat`，並視需要把時間點加進 `skipAhead` 的清單，讓現場展示時可以快轉停在這裡。新增一個畫面時，在 `scenes/` 建立檔案、呼叫 `registerScene`，再到 `main.js` 加一行 import。

新增或修改音效後，需要重新校正響度。做法是在瀏覽器主控台以 `OfflineAudioContext` 建立離線音訊環境，串上近似 K 加權的濾波器（1500 Hz 高頻架 +4 dB、38 Hz 高通），呼叫 `sfx(name, { ctx, master })` 把音效渲染進去，取 200 毫秒滑動視窗的最大均方值換算成 dB，再調整 `SFX_TRIM` 使每個音效落在約 -24 dB。含隨機雜訊的音效（事件卡、蓋章）每次結果會有約 0.5 dB 的差異，取多次平均即可。

## 已知陷阱

p5.js 全域模式會把它所有的函式（如 `noise`、`line`、`text`）設定為全域名稱。若在一般 script 裡用同名的全域函式，p5 啟動時會蓋掉它，而且不會報錯。重構前的音效程式正是如此：自訂的 `noise()` 被 p5 的 Perlin 雜訊函式取代，事件卡與蓋章的雜訊層從未發出聲音。改用 ES 模組後，模組內的名稱不會進入全域，也就不會再被覆蓋。
